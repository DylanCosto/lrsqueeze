# Benchmarks

Whole-genome measurements of what lrsqueeze's archives change for variant calling, structural
variants and CpG methylation, and how large and fast they are. They were run on 2026-11-07 and
2026-11-08 against GIAB v4.2.1, with pasta `3cea7a3`. How to read them, and why the defaults are
what they are, is in [docs/validation-wgs.md](../docs/validation-wgs.md).

The tables here are the raw results, generated by
[`scripts/wgs/collect_benchmarks.py`](../scripts/wgs/collect_benchmarks.py) from the validation
work directory. They contain counts and summary statistics only, not reads or calls.

## Summary: default

Change in F1 against the original BAM, in percentage points, with 95% paired-bootstrap
intervals:

| Dataset | SNP | Indel | Indel, long homopolymers |
|---|---:|---:|---:|
| ONT HG003 SUP | −0.003 [−0.004, −0.002] | −0.0004 [−0.010, +0.010] | −0.006 [−0.027, +0.016] |
| ONT HG002 HAC (chr1–6) | −0.001 [−0.003, +0.000] | −0.084 [−0.106, −0.061] | −0.189 [−0.237, −0.139] |
| PacBio HG002 Revio | −0.001 [−0.002, −0.001] | −0.011 [−0.017, −0.005] | |
| PacBio HG002 HiFi | −0.0006 [−0.0012, +0.0001] | −0.011 [−0.016, −0.005] | |

- **Structural variants:** identical VCFs on ONT SUP, ONT HAC and PacBio HiFi. On PacBio Revio,
  10 of 24,507 PASS calls are lost, from CRAM storing `=`/`X` CIGAR operations as `M`.
- **CpG methylation:** with pb-CpG-tools count mode, methylation %, coverage and counts are
  identical at all 28,934,010 Revio CpG sites. With a modkit-style pileup at a fixed 0.8 threshold,
  5mC changes by 0.39 pp on average on ONT and 0.98 pp on PacBio.
- **Size:** 20–26% of the original BAM.

## Summary: FASTQ

FASTQ is packed with native qualities on homopolymers found in each read (`read_hp5`), measured
on the aligned BAM since aligners ignore qualities. Against the original:

| Dataset | SNP | Indel | Indel, long homopolymers | Against the default, indel |
|---|---:|---:|---:|---:|
| ONT HG003 SUP | −0.003 [−0.004, −0.002] | −0.002 [−0.012, +0.009] | −0.006 [−0.027, +0.016] | −0.0003 [−0.003, +0.003] |
| ONT HG002 HAC (chr1–6) | −0.001 [−0.003, +0.000] | −0.084 [−0.106, −0.063] | −0.191 [−0.240, −0.142] | −0.0007 [−0.008, +0.007] |

SUP is scored on all confident autosomes here. PacBio's default protects no homopolymers, so its
FASTQ policy is the same as for BAM, and `--max` gives each read the mean of its Phred scores in
both. Aligning the ONT chr20 FASTQ with minimap2 before and after
packing gave identical alignments apart from `QUAL` (all 141,939 records), so these calls are
what the packed FASTQ gives.

FASTQ sizes on chr20 reads with `MM`/`ML`, against the original gzip (`-@ 8`; `--max` at BGZF level 10, which was 2.6 times (ONT) and 1.8 times (Revio) as fast as level 12 for files 2.4% and 1% larger):

| Reads | Original | Default | `--max` |
|---|---:|---:|---:|
| ONT HG003 SUP, 72,135 reads | 1,293 MB | 702 MB (54%) | 593 MB (46%) |
| PacBio HG002 Revio, 141,297 reads | 968 MB | 844 MB (87%) | 562 MB (58%)\* |

\* Measured with the mean-error rule; on the whole genome, mean-Phred archives were 0.2% smaller.

|---|---|---:|---|

Each dataset was scored against the reference it was aligned to: ONT's release GRCh38 for ONT,
and the GRCh38 no-alt analysis set for PacBio.

## Conditions

| Condition | Meaning |
|---|---|
| `original` | the input BAM |
| `default` | `lrsqueeze pack` |
| `max` | `lrsqueeze pack --max` |
| `default_cpg_only` | `lrsqueeze pack --methylation cpg-only` |
| `q8_no_hp` | ONT 8 bins without homopolymer protection: the default before protection was added |
| `max_rq`, `max_mean_error` | PacBio `--max` with one quality per read from `rq` (what 0.1.0–0.2.1 did, with mean error for reads without `rq`), or from its mean error probability; `max` is the mean of its Phred scores |
| `read_hpN` | ONT 8 bins with native qualities on homopolymers of at least N bp found in the read's own bases, as FASTQ is packed; measured on the aligned BAM, since aligners ignore qualities (`read_hp5` adopted for FASTQ; see below) |
| `hpN_flankF` | ONT HAC screen of wider homopolymer protection: native qualities on reference runs of at least N bp, plus F bp each side (not adopted; see below) |

## Scopes

| Scope | Regions |
|---|---|
| `primary` | `ont_sup`'s headline scope: GIAB confident autosomes without chr20, which was used in the pilots (2.47 Gb) |
| `autosomes` | all GIAB confident autosomes |

## Files

| File | Contents |
|---|---|
| [`small_variants.tsv`](small_variants.tsv) | RTG vcfeval counts (TP baseline and call, FP, FN), precision, recall and F1, per dataset, condition, scope and type; PASS calls, threshold-free |
| [`bootstrap.tsv`](bootstrap.tsv) | F1 changes with 95% intervals from a paired bootstrap over 10 Mb blocks (20,000 draws) |
| [`structural_variants.tsv`](structural_variants.tsv) | SV concordance with the original's calls: PASS matches, and whether the VCF records are identical |
| [`methylation.tsv`](methylation.tsv) | CpG pileup comparisons with the original (or with `default`, for `default_cpg_only`) |
| [`sizes.tsv`](sizes.tsv) | archive bytes, % of the original, encode wall time and peak memory at `-@ 16` |
| [`hac-homopolymer-screen/`](hac-homopolymer-screen/) | the patch and script for the `hpN_flankF` screen |

In `sizes.tsv`, the rows marked "single-threaded transform" ran the record transform on one
thread, in development builds before 0.1.0 (which transforms records on `-@` threads). That made
`--methylation cpg-only` take 19 minutes instead of 5.5; the other modes were limited by CRAM compression and changed little. One
`max` row also enabled the lzma and bzip2 codecs, which the shipped `--max` leaves off; its
records are the same.

## Tools

- Small variants: lrpipe 0.1.8 `snv`, a Clair3 2.0.3 port, CPU exact mode, 14 threads. Models
  `r1041_e82_400bps_sup_v500`, `r1041_e82_400bps_hac_v500` and `hifi_revio`. The archives were
  read directly as CRAM.
- Scoring: RTG vcfeval 3.13.
- Structural variants: lrpipe 0.1.8 `sv`, a Sniffles2 2.8.1 port.
- Methylation: lrpipe 0.1.8 `methyl pileup --cpg --combine-strands --filter-threshold C:0.8`
  (byte-identical to modkit 0.6.4), and `methyl cpg --pileup-mode count` (matching pb-CpG-tools
  3.0.0).

## Reproducing

[`scripts/wgs/validate_dataset.sh`](../scripts/wgs/validate_dataset.sh) encodes a dataset, calls
small variants and SVs on the original and the archives, and scores them;
[`bootstrap.py`](../scripts/wgs/bootstrap.py), [`sv_compare.py`](../scripts/wgs/sv_compare.py) and
[`compare_bedmethyl_stream.py`](../scripts/wgs/compare_bedmethyl_stream.py) produce the
comparisons. The scripts' default paths are from the machine they ran on; set `W` (the work
directory) and the input arguments for yours. Then:

```sh
python -I scripts/wgs/collect_benchmarks.py WORK_DIR benchmarks
```

### FASTQ homopolymer screen

The `read_hpN`, HAC `q8_no_hp` and PacBio `max` and `max_mean_error` conditions come from
[`scripts/wgs/screen_read_homopolymers.sh`](../scripts/wgs/screen_read_homopolymers.sh), run with
a development build between 0.1.0 and 0.2.0 on HAC (`read5 nohp read4`) and with `DATASET=ont` on SUP (`read5`). It writes
each variant's policy with `homopolymers_in = "read"`, packs the aligned BAM, calls genome-wide
and scores the calls; the bootstrap rows pair each against `original` and `default`.

### HAC homopolymer screen

The `hpN_flankF` conditions came from a build with an experimental `homopolymer_flank` policy
setting, which was dropped because flanks made indels worse.
[`homopolymer-flank.patch`](hac-homopolymer-screen/homopolymer-flank.patch) and
[`screen_homopolymers.sh`](hac-homopolymer-screen/screen_homopolymers.sh) are kept as the record
of that screen: the patch was written against the source before 0.1.0 and does not apply to the
current one. It calls genome-wide: calls restricted to the stratum with Clair3's `--bed_fn` found
about 3,000 fewer true indels there, even with 100 bp padding.
